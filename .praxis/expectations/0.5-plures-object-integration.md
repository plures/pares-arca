# Phase 0.5 Expectations — plures-object NAR Blob Storage

## E-501: NAR import uses plures-object chunked storage
- **Severity:** error
- **Check:** `CacheStore::import_store_path` stores compressed NAR data via `NarObjectStore::put_nar`, not raw filesystem writes to `nar/` directory.
- **Evidence:** `store.rs` calls `self.nar_store.put_nar()` inside `import_store_path`.

## E-502: NAR serve streams from plures-object with filesystem fallback
- **Severity:** error
- **Check:** HTTP `/nar/<file>` endpoint retrieves data from `NarObjectStore::get_nar` first, falls back to legacy `nar/` directory for pre-migration NARs.
- **Evidence:** `arca-server/src/lib.rs` `nar_file` handler tries object store before filesystem.

## E-503: Content deduplication verified
- **Severity:** error
- **Check:** Storing identical NAR content under two different keys results in no additional chunk storage (dedup ratio ≥ 1.9x for identical data).
- **Evidence:** `test_dedup_same_content` test in `object_store.rs` asserts `dedup_ratio() >= 1.9`.

## E-504: Dedup statistics exposed via CLI and API
- **Severity:** error
- **Check:** `status` command and `/api/status` endpoint report `nar_count`, `total_nar_bytes`, `unique_chunk_bytes`, `unique_chunks`, and `dedup_ratio`.
- **Evidence:** CLI `Status` branch calls `nar_store.dedup_stats()`. Server `status` handler includes `object_store` JSON block.

## E-505: NarObjectStore has full CRUD + list
- **Severity:** error
- **Check:** `put_nar`, `get_nar`, `has_nar`, `delete_nar`, `list_nars` all tested.
- **Evidence:** 4 tests in `object_store::tests` covering put/get, dedup, delete, and list.
