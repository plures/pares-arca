# Phase 0.4 — PluresDB Migration Expectations

## E-010: CacheBackend trait exists and is object-safe

**Severity:** error
**Check:** `CacheBackend` trait in `arca-core/src/backend.rs` defines `has`, `get_narinfo`, `put_narinfo`, `list_hashes`, `count`, `total_narinfo_size`. All methods take `&self`. Trait is `Send + Sync`.

## E-011: Filesystem backend implements CacheBackend

**Severity:** error
**Check:** `CacheStore` implements `CacheBackend`. Delegation to existing methods — no behavioral change.

## E-012: Sled backend implements CacheBackend

**Severity:** error
**Check:** `SledStore` in `arca-core/src/sled_store.rs` implements `CacheBackend`. Opens sled DB at configurable path. Key = hash, value = narinfo text.

## E-013: Backend conformance tests pass for both implementations

**Severity:** error
**Check:** `tests/backend_conformance.rs` runs identical put/get/has/list/count assertions against both `CacheStore` and `SledStore`.

## E-014: Audit log records events with timestamps

**Severity:** error
**Check:** `AuditLog` in `arca-core/src/audit.rs` stores events in a sled tree. Events have `timestamp_ms`, `event_type` (Import/SyncReceive/Serve/GarbageCollect), `store_path`, `metadata`. `query_since(timestamp)` returns filtered results.

## E-015: CLI accepts --backend flag

**Severity:** error
**Check:** `pares-cache --backend filesystem|sled` selects storage backend. Default: `filesystem`. `--db-path` sets sled database location.

## E-016: PluresDB integration path is clear

**Severity:** warning
**Rationale:** PluresDB uses sled internally. The `SledStore` is the foundation — PluresDB wraps sled with CRDT semantics, indexing, and replication. Phase 0.5 replaces `SledStore` with a `PluresDbStore` that implements `CacheBackend` using PluresDB's sled instance.
