# Milestone 0.3: Segmented Caches

## Feature Expectations

### E-001: keygen produces cryptographically random topic key
- WHEN: user runs `pares-arca keygen`
- THEN: outputs a 256-bit hex-encoded random key
- AND: key is generated from OS CSPRNG (not pseudo-random)
- SEVERITY: error

### E-002: Config file defines cache segments
- WHEN: config file exists at ~/.config/pares-arca/config.toml
- THEN: each segment has: name, topic_key, description, filter (nixpkgs|custom|all)
- AND: config is validated on startup (missing required fields = error)
- SEVERITY: error

### E-003: Universal segment is default
- WHEN: no config file exists
- THEN: pares-arca creates default config with universal nixpkgs segment
- AND: universal segment uses well-known topic key
- AND: user can remove universal segment from config
- SEVERITY: error

### E-004: Post-build hook routes to correct segment
- WHEN: nix builds a store path
- THEN: post-build hook determines if path is from nixpkgs or custom
- AND: imports to the matching segment's cache
- AND: if no matching segment, imports to default segment
- SEVERITY: error

### E-005: Custom segment requires explicit key
- WHEN: user adds a custom segment to config
- THEN: segment must have a topic_key field
- AND: startup fails with clear error if topic_key is missing
- SEVERITY: error
